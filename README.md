# 集装箱过闸记录查询（港区）

Flask + SQLite 的查箱网页：按批号上传/更正过闸流水 CSV，按箱号查询命中行，
并可为每份现用原件构建 ≤ 2 KiB 的布隆过滤器，查询时跳过不可能命中的批次原件。

## 快速开始

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

SQLite 数据库保存在命名卷 `gate-data`（容器内 `/data/gate.db`），重启不丢数据。

### 本地开发

```bash
python3 -m venv .venv && .venv/bin/pip install -r app/requirements.txt
DATABASE_PATH=/tmp/gate.db .venv/bin/python app/app.py
```

## 使用说明

- **上传 / 更正**：首页填写批号并选择 CSV。同批号再次上传即**更正**：
  文件仍按原规则**整份校验**（任一数据行非法则整份拒绝），通过后批次照常**版本号 +1**；
  归一化后**同一行号上箱号与 UTC 时刻都相同的明细行直接复用**，SQLite 只对
  **新增、改动、删去**的明细行执行写入（未改动的行保留其最初写入时的版号，不产生写入）。
  更正成功即作废旧过滤器；整个更正包在一个写事务内，写入失败整体回滚，原版与原索引照常可查。
- **CSV 格式**：两列 `箱号,UTC过闸时刻`，UTF-8（可带 BOM），数据行 1~5000 行。
  - 箱号：字母/数字/`.-_`，1~64 字符，录入与查询统一去空格并转大写。
  - 时刻：ISO 8601。带时区（如 `+08:00`、`Z`）归一化为 UTC；无时区按 UTC 处理。
  - 表头：仅当第一行第二列不是合法时刻、且第一列是常见表头词（`箱号`、`container` 等）
    或不符合箱号格式时，第一行按表头跳过；否则按数据行严格校验。
- **查询**：按箱号列出命中行（批号、**所查批次当前版号**、行号、UTC 时刻）；
  同一箱号的重复记录按各自行号逐笔列出。同时给出**实际扫描过的批次**和被同版过滤器**跳过的批次**。
- **建立布隆过滤器**：批次列表逐批点击，后台构建（≤ 2 KiB）。
  同版过滤器判定箱号不存在 → 跳过该批原件；否则逐行核对原件。

## 并发与一致性设计

| 要求 | 实现 |
| --- | --- |
| 一次查询使用同一已提交状态的版号、明细和索引 | 整个查询包在**一个读事务**里（WAL 快照）：批次版本、过滤器、明细行三者一致；期间的更正/建索引对本查询不可见 |
| 建索引时同批照常更正、查询 | 过滤器在后台线程构建；构建只读快照、计算在内存，提交是短写事务；更正与查询不因此阻塞 |
| 迟到的旧索引不得覆盖新版索引 | 构建提交是**条件更新**：`UPDATE batches ... WHERE id=? AND version=? AND building_version=?`；批次已前进则更新 0 行，旧过滤器直接丢弃不入库 |
| 构建失败仍可查明细 | 失败仅把批次标记为 `failed`；查询只在 `filter_version == 当前版本` 且过滤器就绪时才用过滤器，否则一律回退逐行扫描明细 |
| 更正只写变化的明细行 | 单写事务内按行号做三向 diff：箱号与 UTC 时刻都相同的行复用（零写入），仅 INSERT/UPDATE/DELETE 新增、改动、删去的行；批次版本照常 +1，旧版本过滤器作废 |
| 写入失败不影响线上查询 | 更正全程一个写事务，任一步失败即 ROLLBACK：批次版号、明细行、过滤器全部回到更正前状态 |
| 旧库直接升级 | `init_db` 识别 v1 结构（`rows` 主键含 `batch_version`），在单事务内重建 `rows` 表（新主键 `(batch_id, line_no)`），批次版号、明细行（含各行版号）、可用过滤器原样保留；`PRAGMA user_version` 标记到 2，迁移可重试、过程原子 |

数据表（v2）：`batches`（批号、版本、行数、过滤器指针）、
`rows`（主键 `(batch_id, line_no)`，`batch_version` 记录该行最后写入时的版号）、
`filters`（按批号+版本存过滤器，blob ≤ 2048 B）。

## HTTP / JSON 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 首页（批次列表、上传与查询表单） |
| POST | `/batches` | 上传/更正，表单字段 `batch`、`file` |
| POST | `/batches/<批号>/filter` | 后台构建过滤器；表单字段 `delay`（秒，≤10）为**测试钩子**，模拟慢构建 |
| GET | `/query?container=<箱号>` | 查询结果页；加 `&format=json` 返回 JSON |
| GET | `/api/batches` | 批次状态 JSON（版本、过滤器状态等） |

## 已知限制 / 未完成

- 无登录鉴权与 CSRF 防护，按内网工具定位；对外部署需加网关或补认证。
- 使用 Flask 内置服务器（threaded），适合科室级并发；更大规模可换 gunicorn（单 worker 多线程即可，构建互斥由数据库保证）。
- 布隆过滤器有误报（5000 行满批、2 KiB 上限下约 20%）：误报只会多扫一个批次，不影响结果正确性；绝不会漏查（无假阴性，已测）。
- 未提供批次删除界面（可整份覆盖）；更正只保留当前版批次的明细行，被删行不保留历史；
  未改动明细行的行内 `batch_version` 是其最后写入时的版号（查询呈现统一用批次当前版号）。
- 本仓库交付环境无 Docker，`docker compose` 未实际启动过；Compose/Dockerfile 本次未改动、
  已经静态检查（构建上下文 `./app`、卷 `gate-data` 挂载到 `/data`、健康检查与端口 8000 均有效），
  且镜像内启动命令 `python app.py` 与本地冒烟验证的路径完全一致。
